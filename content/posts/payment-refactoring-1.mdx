# 결제 시스템 리팩토링 1편 — 문제 정의

## 배경

운영 중인 결제 시스템은 3년 전에 만들어졌습니다. 당시에는 요구사항이 단순했지만, 시간이 지나면서 복잡도가 급격히 증가했습니다.

## 주요 문제점

### 1. 거대한 서비스 클래스

```java
public class PaymentService {
    // 2000줄이 넘는 단일 클래스
    public PaymentResult processPayment(PaymentRequest request) {
        // 결제 수단별 분기가 중첩되어 있음
    }
}
```

### 2. 테스트 불가능한 구조

외부 의존성이 직접 주입되어 있어 단위 테스트가 어렵습니다.

### 3. 에러 처리의 부재

실패 시 재시도 로직이 없고, 에러 메시지가 불명확합니다.
